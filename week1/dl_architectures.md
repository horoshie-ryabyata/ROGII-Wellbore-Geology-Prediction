## 1. Понимание задачи

### Что дано

- **Горизонтальная скважина**: длинная "труба", идущая под землёй. На каждой точке (через каждый фут) измеряется GR (Gamma Ray).
- **Типовая (вертикальная) скважина**: эталон, для которого известны и GR, и TVT (геологическая глубина), и слой геологии.
- **TVT_input**: известная часть TVT горизонтальной скважины — до точки PS (Prediction Start).

### Что нужно

Предсказать TVT для горизонтальной скважины **после точки PS**.

### Почему это задача для DL

1. **GR — это 1D-сигнал.** DL отлично работает с сигналами через 1D CNN.
2. **Нужно сопоставлять две последовательности** (горизонталка ↔ типовая). Это идеально для **attention-механизмов**.
3. **Локальные паттерны GR — это сигнатура слоя.** CNN их извлекает.
4. **Длинные зависимости** (скважина может быть 10000+ точек). LSTM/Transformer справляются.
5. **Few-shot ситуация**: для каждой скважины есть размеченная часть до PS. Можно делать fine-tuning под конкретную скважину.

## 2. Особенности данных

### Что делает задачу сложной

| Проблема | Описание | Как с этим бороться |
|----------|----------|---------------------|
| **Разная длина скважин** | От 5000 до 20000+ точек | Padding/cropping или работа окнами |
| **NaN в GR** | Иногда инструменты глючат | Заполнение медианой/интерполяцией |
| **Шум в GR** | Природный + инструментальный | Аугментация шумом, сглаживание |
| **Длинные плоские участки** | Бур идёт вдоль слоя, GR не меняется | Использовать TVT_input до PS как якорь |
| **Разный масштаб GR** между скважинами | Кто-то откалиброван иначе | Per-well нормализация |
| **Разломы (faults)** | GR резко скачет | Robust loss (Huber вместо MSE) |
| **Дрейф TVT** | TVT варьируется от 11000 до 13000 | Предсказывать дельту от last_known |

### Ключевая идея для целевой переменной

Вместо предсказания TVT (которое сильно варьируется), мы предсказываем **дельту от last_known_tvt** — последнего известного значения в точке PS.

```python
y = TVT - last_known_TVT  # Стационарная цель!
```

Это резко улучшает обучаемость, потому что:
- Распределение target'а — почти нормальное, около нуля
- Модель учится локальным паттернам, а не "запоминанию" значений
- Если что-то ломается — предсказания не уходят далеко от last_known

## 3. Базовая модель: 1D CNN

### Архитектура

```
Окно GR горизонтальной (1×201)        GR типовой (1×1500)
        ↓                                    ↓
   Conv1D 32 (k=7)                    Conv1D 32 (k=7)
   Conv1D 64 (k=5)                    Conv1D 64 (k=5)
   MaxPool 2                          MaxPool 4
   Conv1D 128 (k=3)                   Conv1D 128 (k=3)
   AdaptiveAvgPool → 128              AdaptiveAvgPool → 128
        ↓                                    ↓
        └──────────┬─────────────────────────┘
                   ↓
       Concat [128 + 128 + 3 скаляров]
                   ↓
              MLP (128 → 64 → 1)
                   ↓
              Предсказание TVT (или дельты)
```

### Почему это хороший старт

- ✅ **Простая** — легко понять, отладить, улучшить
- ✅ **Быстрая** — обучается за 20-40 минут на одном GPU
- ✅ **Понятная** — каждый слой имеет смысл
- ✅ **Базовая** — служит точкой отсчёта для всех улучшений

### Гиперпараметры (стартовые)

| Параметр | Значение | Почему |
|----------|----------|--------|
| Размер окна | 201 (±100) | Достаточно контекста, не слишком много |
| Размер ядра CNN | 7, 5, 3 | От большого к малому — захват разных масштабов |
| Channels | 32 → 64 → 128 | Стандартный паттерн roughly удвоения |
| Optimizer | AdamW | Стабильнее обычного Adam |
| Learning rate | 1e-3 | Стандарт для AdamW |
| Loss | Huber (δ=10) | Устойчив к выбросам |
| Scheduler | CosineAnnealing | Плавное снижение lr |

### Ожидаемый результат

CV RMSE: **8-15** (зависит от данных). Это уже намного лучше константного бейзлайна.

## 4. Улучшение: U-Net 1D

### Зачем

CNN с avg pooling **теряет информацию** о точном положении паттернов. U-Net решает это через **skip connections** — пропускает признаки разных уровней разрешения напрямую в декодер.

### Архитектура

```
INPUT (1, 201)
    ↓
  ┌──────────┐                          ┌──────────┐
  │ ConvBlock│──── skip connection ───→│ ConvBlock│ → OUTPUT
  │  (32)    │                          │   (32)   │
  └──────────┘                          └──────────┘
       ↓ pool                                 ↑ upsample
  ┌──────────┐                          ┌──────────┐
  │ ConvBlock│──── skip ─────────────→  │ ConvBlock│
  │  (64)    │                          │   (64)   │
  └──────────┘                          └──────────┘
       ↓ pool                                 ↑ upsample
  ┌──────────┐                          ┌──────────┐
  │ ConvBlock│──── skip ─────────────→  │ ConvBlock│
  │  (128)   │                          │   (128)  │
  └──────────┘                          └──────────┘
       ↓ pool                                 ↑ upsample
  ┌──────────┐
  │ ConvBlock│  ← bottleneck (256 channels)
  │  (256)   │
  └──────────┘
```

### Когда внедрять

**Неделя 3-4.** После того, как CNN-бейзлайн стабильно работает.

### Ожидаемое улучшение

**+10-15% к RMSE** относительно простой CNN.

## 5. Глобальный контекст: Bi-LSTM

### Проблема CNN

CNN видит только **локальный контекст** (например, ±100 точек). Но в длинной скважине порой нужны **дальние связи** — например, если бур недавно прошёл через ANCC, то скоро будет ASTNU.

### Решение

Поверх CNN-энкодера добавить **Bi-LSTM** или **GRU**, которая видит всю последовательность:

```
GR-сигнал длины L
    ↓
1D CNN (извлекает локальные фичи на каждой позиции)
    ↓
последовательность эмбеддингов (L × 128)
    ↓
Bi-LSTM (видит весь контекст в обе стороны)
    ↓
последовательность скрытых состояний (L × 256)
    ↓
Linear → предсказание TVT на каждой позиции
```

### Когда внедрять

**Неделя 5.** Когда понятно, что локальных паттернов недостаточно.

### Альтернатива: TCN

**Temporal Convolutional Network** (TCN) — это как Bi-LSTM, но через dilated convolutions. Быстрее в обучении, но требует больше параметров.

```python
from torch.nn.utils import weight_norm

class TCNBlock(nn.Module):
    def __init__(self, ch_in, ch_out, dilation):
        super().__init__()
        self.conv = weight_norm(nn.Conv1d(ch_in, ch_out, 3,
                                            padding=dilation, dilation=dilation))
```

## 6. Сопоставление: Cross-Attention

### Главная идея задачи

Нам нужно **сравнить** GR горизонталки с GR типовой. На каждой точке горизонталки спросить: "На какую точку типовой я больше всего похож?"

Это **классическая задача attention'а**.

### Архитектура Cross-Attention

```
Query = эмбеддинги горизонталки    (B, L_h, D)
Key   = эмбеддинги типовой         (B, L_t, D)
Value = эмбеддинги типовой         (B, L_t, D)

Attention(Q, K, V) = softmax(Q @ K^T / √D) @ V

→ Каждая точка горизонталки получает взвешенную сумму
   точек типовой, где веса = их похожесть.
```

### Реализация в PyTorch

```python
class CrossAttention(nn.Module):
    def __init__(self, dim, num_heads=4):
        super().__init__()
        self.attn = nn.MultiheadAttention(dim, num_heads, batch_first=True)
        self.norm = nn.LayerNorm(dim)
    
    def forward(self, query_seq, key_value_seq):
        # query_seq: [B, L_h, D]
        # key_value_seq: [B, L_t, D]
        out, attn_weights = self.attn(query_seq, key_value_seq, key_value_seq)
        return self.norm(query_seq + out), attn_weights
```

### Бонус: интерпретируемость

`attn_weights` показывают, **куда смотрит модель** в типовой для каждой точки горизонталки. Можно визуализировать как heatmap — это очень полезно для отладки и понимания.

### Когда внедрять

**Неделя 6-7.** Это уже продвинутая техника.

### Ожидаемое улучшение

**+5-10%** относительно U-Net без attention.

## 7. Финальное оружие: Transformer

### Идея

Transformer — это **Cross-Attention + Self-Attention + FFN + Residuals**.

Архитектура:

```
INPUT (горизонталка + типовая)
        ↓
  Embedding слой (1 → D)
        ↓
  Positional Encoding (добавляем информацию о позиции)
        ↓
┌──── Transformer Encoder Block × N ────┐
│                                        │
│   Self-Attention                       │
│   (горизонталка ↔ горизонталка)        │
│        ↓                                │
│   Cross-Attention                      │
│   (горизонталка ↔ типовая)             │
│        ↓                                │
│   Feed-Forward                         │
│        ↓                                │
│   LayerNorm + Residual                 │
│                                        │
└────────────────────────────────────────┘
        ↓
   Linear → TVT
```

### Размер модели

Для нашей задачи:
- `d_model = 128`
- `num_heads = 8`
- `num_layers = 4-6`
- `feedforward_dim = 512`

Это **~1-3M параметров** — не слишком много, но достаточно для качественного обучения.

### Когда внедрять

**Неделя 6-7.** После того, как простые модели работают и понятны их ограничения.

### Сложности

- Долго обучается (1-3 часа на GPU)
- Чувствителен к learning rate (нужен warmup)
- Может переобучаться → нужны dropout и augmentation

## 8. Сиамские сети

### Идея

Сделать **единый энкодер** GR-сигнала. Цель — научить его так, что **похожие куски GR имеют похожие эмбеддинги**, а разные — далёкие.

Это **contrastive learning** — обучение представлений через сравнения.

### Архитектура

```
GR-окно ─── Encoder ──→ embedding_1
                          
                          
GR-окно ─── (тот же)  ──→ embedding_2
            Encoder
                          
            ↓
    contrastive_loss(emb_1, emb_2, label)
```

Где `label = 1`, если оба окна — это одна и та же геология (тот же слой), и `label = 0` — иначе.

### Loss

**Triplet Loss** или **InfoNCE**:

```python
# Triplet loss
loss = max(0, d(anchor, positive) - d(anchor, negative) + margin)

# InfoNCE (более современный)
loss = -log(exp(sim(q, k+)) / sum(exp(sim(q, k_i))))
```

### Применение в нашей задаче

1. Обучить сиамский энкодер на парах из тренировочных данных
2. Использовать его как **feature extractor** для основной модели
3. На инференсе: каждое окно горизонталки → эмбеддинг → ищем ближайший в типовой → TVT

### Когда внедрять

**Неделя 7-8.** Это уже исследовательская территория.

## 9. Техники улучшения

### 9.1. Few-shot Fine-tuning ⭐⭐⭐ **САМОЕ ВАЖНОЕ!**

Для каждой тестовой скважины у нас есть **известная часть до PS**. Это бесплатные пары (GR, TVT) для этой конкретной скважины.

**Идея**: дообучить базовую модель на этой известной части, чтобы она "выучила" специфику данной скважины.

```python
def predict_with_finetuning(base_model, test_well):
    # 1. Копия модели
    model = copy.deepcopy(base_model)
    
    # 2. Замораживаем энкодеры (не хотим их менять сильно)
    for param in model.encoder_horizontal.parameters():
        param.requires_grad = False
    
    # 3. Дообучаем только голову на известной части
    known_part = test_well[:ps_idx]
    train_for_few_epochs(model, known_part, lr=1e-4, epochs=5)
    
    # 4. Предсказываем после PS
    return model.predict(test_well[ps_idx:])
```

**Ожидаемое улучшение: +5-15%** к финальному score. Это часто решающий буст в задачах геологии.

### 9.2. Multi-Seed Averaging

Обучаем 5 моделей с разными seed → усредняем предсказания.

```python
preds = []
for seed in [42, 1337, 2024, 7, 100]:
    torch.manual_seed(seed)
    model = train_model()
    preds.append(model.predict(test))

final_pred = np.mean(preds, axis=0)
```

Стабильно даёт **+1-3%** к RMSE.

### 9.3. Snapshot Ensembling

Сохраняем чекпоинты каждые N эпох → усредняем их веса (или предсказания).

### 9.4. Pseudo-labeling

1. Предсказываем TVT на тесте.
2. Берём самые **уверенные** предсказания.
3. Добавляем их в train.
4. Переобучаем модель.

### 9.5. Test-Time Augmentation (TTA)

На инференсе делаем **несколько проходов** с разными аугментациями (шум, сдвиги), усредняем.

### 9.6. Mixup на сигналах

Для регуляризации:

```python
mixed_gr = lambda * gr_1 + (1 - lambda) * gr_2
mixed_target = lambda * y_1 + (1 - lambda) * y_2
```

### 9.7. Loss функции

| Loss | Когда применять |
|------|-----------------|
| **MSE** | Стандарт, но чувствителен к выбросам |
| **Huber** | Робастный, рекомендуется по умолчанию |
| **Smooth L1** | Похож на Huber |
| **Quantile** | Если хотим знать неопределённость |

## 📝 Заключение

Главная стратегия: **от простого к сложному**.

1. **Сначала** убеждаемся, что CNN работает (sanity check).
2. **Потом** масштабируем (U-Net, Bi-LSTM).
3. **Потом** добавляем главную фичу задачи — сопоставление через **Cross-Attention**.
4. **В конце** применяем few-shot fine-tuning — это будет наш главный буст.

**Главный риск**: уйти в сложные модели без проверки базовой. Это путь в никуда.

**Главный шанс**: правильно сделанный **few-shot fine-tuning + ансамбль с командой A** даёт топ-10%.
